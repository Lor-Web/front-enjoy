В основном уроке пропсы — аргументы: `name`, `price`, родитель передаёт, карточка рисует. Дальше — как устроен объект пропсов, слот `children` и почему карточку нельзя «подкрутить» изнутри.

## Один объект на вход

Вызов `<DrinkCard name="Латте" price={280} />` не передаёт два отдельных аргумента функции. React собирает их в **один объект** и отдаёт первым параметром:

```jsx
function DrinkCard(props) {
  // props === { name: "Латте", price: 280 }
  return <h3>{props.name}</h3>;
}
```

Деструктуризация `{ name, price }` — удобная запись того же объекта. Поля, которые не разобрали, никуда не делись: их можно взять через rest.

```jsx
function DrinkCard({ name, price, ...rest }) {
  return <article className="card" {...rest} />;
}
```

`rest` на DOM-узел тащит всё оставшееся: `id`, `aria-*`, `data-*`. На свою карточку так делают, когда оборачивают нативный тег. На чужие данные кафе (`isHit`, `inStock`) spread лучше не вываливать в `article`: лишние атрибуты окажутся в HTML.

## Значения по умолчанию

Если бейдж «хит» нужен редко, не заставляйте каждый вызов писать `isHit={false}`. Значение по умолчанию — в сигнатуре:

```jsx
function DrinkCard({ name, price, isHit = false, inStock = true }) {
  return (
    <article>
      <h3>
        {name}
        {isHit ? " · хит" : null}
      </h3>
      <p>{inStock ? `${price} ₽` : "Нет в наличии"}</p>
    </article>
  );
}

<DrinkCard name="Эспрессо" price={180} />
<DrinkCard name="Латте" price={280} isHit />
```

Булево `isHit` без `={true}` в JSX значит `true`. Это тот же проп, короче запись.

Старый `DrinkCard.defaultProps = {…}` в функциях больше не нужен: хватает параметров. Классы — отдельная история, в новом коде кафе их нет.

## children — слот, не «ещё одно поле»

Всё, что стоит **между** открывающим и закрывающим тегом, приходит как `props.children`:

```jsx
function Card({ children }) {
  return <article className="card">{children}</article>;
}

function DrinkCard({ name, price }) {
  return (
    <Card>
      <h3>{name}</h3>
      <p>{price} ₽</p>
    </Card>
  );
}
```

Так собирают рамку: `Card` не знает, латте внутри или «сегодня закрыто». Не плодите `title`, `body`, `footer`, `extra`, если достаточно вложить разметку. Именованные слоты (`header`, `actions`) появляются, когда детей несколько и их нельзя отличить порядком.

`children` тоже только для чтения. Не делайте `children.push(...)`.

## Объект целиком или поля

Пока полей два — явно: `name={drink.name} price={drink.price}`. Когда появятся `isHit`, `inStock`, описание, объём, удобнее один объект:

```jsx
function DrinkCard({ drink }) {
  return (
    <article className="card">
      <h3>{drink.name}</h3>
      <p>{drink.price} ₽</p>
    </article>
  );
}

<DrinkCard drink={latte} />
```

Минус: карточка зависит от формы `drink`. Плюс: родитель не перечисляет десять атрибутов. Для меню «Зёрнышка» на 4–5 полях объект уже уместен; для двух — поля читаемее.

Не передавайте «весь мир»: `user`, `theme`, `router`, `drinks`, если карточке нужна только цена. Лишние пропсы — лишние причины перерисоваться, когда дойдёте до мемоизации.

## Родитель владеет данными

Пропсы — снимок на этот рендер. Карточка не пишет `price = price - 10` и не делает `drink.inStock = false`. Даже если объект пришёл по ссылке и технически мутация сработает, React об этом не узнает: он сравнивает данные, которые вы ему отдали снаружи.

Нужна новая цена — меняют источник в родителе и передают новое значение. Это та же формула «экран = f(данные)». Состояние, которое умеет меняться, будет в конце трека. До него считайте пропсы замороженными.

## Что запомнить

- Пропсы — один объект, не список аргументов как у `add(a, b)`.
- Значения по умолчанию пишут в параметрах, булев флаг можно без `={true}`.
- `children` — слот для вложенной разметки.
- Данные меняет тот, кто их хранит, не карточка.
