Пропсы держат границу: меню знает список, карточка знает, как нарисовать один напиток. Ниже — как не размыть эту границу.

## Не мутируйте пропсы

```jsx
function DrinkCard({ drink }) {
  drink.price = drink.price - 30; // так нельзя
  return <p>{drink.price} ₽</p>;
}
```

Даже «временно, только для скидки». Скидку считают в переменной или считает родитель. Мутация объекта из пропсов — общий `latte` в меню внезапно дешевеет у всех карточек, а экран может не обновиться.

## Перечисляйте контракт

Spread экономит строки и прячет, что карточка на самом деле ждёт.

```jsx
const latte = {
  name: "Латте",
  price: 280,
  isHit: true,
  inStock: true,
  description: "Эспрессо с молоком",
};

<DrinkCard {...latte} />
```

По тегу не видно, читает ли `DrinkCard` описание или проигнорирует его. Пока учитесь — пишите поля явно:

```jsx
<DrinkCard
  name={latte.name}
  price={latte.price}
  isHit={latte.isHit}
  inStock={latte.inStock}
/>
```

Контракт на ладони: четыре пропа, не «весь объект напитка». Spread на `DrinkCard` уместен, когда объект **уже** является её пропсами один в один и это сознательно.

На DOM rest нормален: вы пробрасываете `disabled`, `aria-label`, не данные кафе.

```jsx
function CafeButton({ children, ...rest }) {
  return (
    <button type="button" className="btn" {...rest}>
      {children}
    </button>
  );
}

<CafeButton disabled aria-label="Добавить латте в заказ">
  В заказ
</CafeButton>
```

Не смешивайте поля напитка и HTML-атрибуты в одном объекте: иначе `isHit` окажется атрибутом на `article`.

## Дефолты в сигнатуре

```jsx
function DrinkCard({ name, price, isHit = false }) {}
```

Не `defaultProps` у функции и не `if (isHit === undefined)` в каждой строке. Явное `= false` читается в одном месте.

Булево «да» в JSX: `isHit`, не `isHit={true}`. «Нет» лучше не писать, если сработал дефолт.

## children вместо десятого пропа

Если в карточку кладут то бейдж, то кнопку, то подпись — не плодите проп на каждый кусок разметки.

```jsx
function DrinkCard({ name, price, badge, footnote, extraButton }) {
  return (
    <article className="card">
      <h3>
        {name} {badge}
      </h3>
      <p>{price} ₽</p>
      {footnote}
      {extraButton}
    </article>
  );
}

<DrinkCard
  name="Латте"
  price={280}
  badge={<span className="badge">Хит</span>}
  extraButton={<button type="button">В заказ</button>}
/>
```

Слот `children` — всё, что стоит между тегами. Рамка одна, содержимое разное:

```jsx
function DrinkCard({ name, price, children }) {
  return (
    <article className="card">
      <h3>{name}</h3>
      <p>{price} ₽</p>
      {children}
    </article>
  );
}

<DrinkCard name="Латте" price={280}>
  <span className="badge">Хит</span>
  <button type="button">В заказ</button>
</DrinkCard>
```

Именованный слот заводите, когда два региона нельзя перепутать порядком: например, `actions` справа от названия. До этого — дети.

## Не прокидывайте лишнее

Карточке не нужен весь `cafe`, весь `user` и соседние напитки. Чем уже пропсы, тем проще тестировать и тем меньше сюрпризов, когда в шапке сменилось имя баристы, а латте перерисовался.

Когда полей стало много и они всегда ездят вместе — один объект `drink`. Когда поле одно — одно поле.

## Кто меняет данные

Цена, наличие, «хит» живут в `Menu` (позже — в состоянии выше). `DrinkCard` показывает. Если карточка начинает «сама решать», что какао закончилось, появятся два источника правды.

## Что запомнить

- Пропсы читают, не пишут.
- Контракт виден в теге, не спрятан в spread.
- Дефолты — в параметрах, слоты — через `children`.
- Карточка узкая: только то, что рисует.
