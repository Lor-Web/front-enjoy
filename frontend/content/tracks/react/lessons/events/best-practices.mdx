Клики в кафе должны делать одно понятное действие. Большая часть багов — вызвали функцию слишком рано или забыли про форму.

## Не ставьте скобки в onClick

```jsx
<button type="button" onClick={handleAdd()}>
  В заказ
</button>
```

Так `handleAdd` бежит на каждый рендер. Нужна ссылка:

```jsx
<button type="button" onClick={handleAdd}>
  В заказ
</button>
```

Аргумент — обёртка, не вызов внутри пропа:

```jsx
onClick={() => onAdd(drink.id)}
```

Не `onClick={onAdd(drink.id)}`.

## type="button" по умолчанию

Любая кнопка «сделать что-то на странице», не «отправить форму»:

```jsx
<button type="button" onClick={handleAdd}>
  В заказ
</button>
```

`type="submit"` оставляйте одной кнопке оформления. Иначе Enter в инпуте сработает как «В заказ» или перезагрузит страницу.

## Форму останавливают явно

```jsx
function handleSubmit(event) {
  event.preventDefault();
  // отправить заказ
}
```

Не надейтесь на `return false` из jQuery — в React это не отменяет submit.

## Имена: on… вниз, handle… внутри

```jsx
<DrinkCard onAdd={handleAdd} />
<SearchBar onSubmit={handleSearch} />
```

Проп говорит, **когда** звать родителя. Функция в родителе говорит, **что** сделать. Не называйте проп `handleAdd` — снаружи это событие, не реализация.

## Не addEventListener в рендере

```jsx
function Menu() {
  document.addEventListener("click", handleAnywhere);
  return <section>Меню</section>;
}
```

Каждый рендер — ещё один слушатель. Клики начнут приходить пачками. Для кафе хватает `onClick` на кнопке. Глобальные слушатели, если когда-нибудь понадобятся, живут в эффекте (это уже другой урок).

## stopPropagation — исключение

Останавливайте всплытие, только когда два обработчика на вложенных узлах мешают друг другу и вы это понимаете. В меню из кнопки и текста карточки чаще проще повесить `onClick` только на кнопку.

## Что запомнить

- Ссылка на функцию, не вызов.
- `type="button"` + `preventDefault` у форм.
- Событие наверх через `onAdd`, логика в родителе.
- Без ручных `addEventListener` и без лишнего `stopPropagation`.
