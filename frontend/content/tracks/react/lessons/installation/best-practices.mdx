Окружение ломается чаще, чем JSX. Эти правила экономят часы ещё до первого компонента «Зёрнышка».

## Один менеджер пакетов

Выберите npm **или** pnpm **или** yarn и не меняйте его без причины. В репозитории один lock-файл. Его **коммитят**: так у коллеги и у CI встанут те же версии, что у вас.

`node_modules` в git не кладут. В `.gitignore` шаблона Vite это уже есть — не удаляйте строку.

## Зафиксируйте Node

Команда `npm create vite` на Node 16 и на Node 22 ведёт себя по-разному. Для проекта кафе достаточно текущей LTS.

Практичный минимум:

- в `package.json` поле `"engines": { "node": ">=20" }`;
- рядом файл `.nvmrc` с тем же номером, если команда пользуется nvm/fnm.

Так вы не ловите «у меня работает» из-за разной мажорной версии.

## Не берите Create React App

CRA официально не развивается. Статьи 2019 года с `npx create-react-app` для нового проекта — устаревший путь. Для SPA берите Vite (или фреймворк, если он правда нужен).

Готовые «супер-стартеры» с пятьюдесятью библиотеками тоже опасны: вы учите чужой каркас, а не React. Учебный шаблон с `react` + `react-dom` + Vite — нормальная база.

## Одна копия React

Две версии `react` в дереве зависимостей дают загадочные ошибки хуков: «Invalid hook call». Не ставьте React вручную «ещё раз» в подпапку, не линкуйте пакеты вслепую.

Проверка, если что-то странное: `npm ls react`. Должна быть одна ветка той версии, что в `package.json`.

## StrictMode оставляйте

Выключать `<StrictMode>` чтобы «перестало двойниться» — прятать симптом. Лучше убрать побочный эффект из рендера: логи, запись в модульную переменную, запрос в теле функции.

Пока у «Зёрнышка» нет эффектов, двойной вызов вам почти не мешает. Когда появится `useEffect` — строгий режим как раз покажет лишние подписки.

## Dev-сервер не для продакшена

`npm run dev` держит исходники, исходные карты, HMR. Это неудобно по скорости и небезопасно как публичная точка.

На хостинг: `npm run build`, в настройках — папка `dist`. `vite preview` — только чтобы самим посмотреть билд.

## Секреты не в клиенте

Всё, что начинается с `VITE_`, попадает в бандл. Ключ от платёжки, пароль БД, приватный токен API так не хранят. Для «Зёрнышка» переменные пока не нужны; когда понадобится API-адрес, туда кладут публичный URL, не секрет.

`.env` с секретами не коммитят. `.env.example` без значений — можно.

## createRoot вызывают один раз

Второй `createRoot(el).render(...)` на том же узле — отдельное дерево и сюрпризы. Точка входа одна: `main.jsx`. Тесты и Storybook монтируют свой корень сами; учебное приложение — нет.

Не смешивайте `createRoot` с устаревшим `ReactDOM.render` в одном файле.

## Когда добавлять TypeScript

Шаблон `react-ts` хорош, если вы уже пишете типы. Если цель урока — компоненты и JSX, JS-шаблон честнее: меньше шума. Переехать позже можно. Не добавляйте TypeScript «на всякий случай» в середине первого дня — сначала доведите меню до состояния, которое понимаете.

## Что запомнить

- Lock-файл — в git, `node_modules` — нет.
- Одна версия Node, один менеджер пакетов, одна копия React.
- Vite в `dev` локально, `build` — на хостинг.
- StrictMode и `createRoot` не выключают и не дублируют.
