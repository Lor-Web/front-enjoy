Основное даёт рабочий путь: Node → Vite → `npm run dev`. Здесь разберём, **почему** так, что ещё бывает в 2025–2026 и где люди обычно ломают окружение.

## Зачем вообще сборщик

Браузер не понимает JSX и плохо дружит с сотнями файлов `import`. Сборщик (у нас Vite) на разработке:

- превращает JSX в вызовы React;
- склеивает модули и отдаёт браузеру то, что он умеет;
- поднимает HMR: сохранили файл — экран обновился без полной перезагрузки.

В продакшене он собирает оптимизированный бандл: минификация, разбиение на чанки, дерево зависимостей без «мёртвого» кода.

Открыть `index.html` двойным щелчком и ждать React — путь в никуда. Точка входа всегда такая: Node-процесс отдаёт страницу, React монтируется в `#root`.

## Что лежит в шаблоне Vite

После `npm create vite@latest zernyshko -- --template react` важны не картинки на стартовом экране, а роли файлов.

- `index.html` — единственная HTML-страница. В ней `#root`.
- `src/main.jsx` — `createRoot(...).render` корневого компонента.
- `src/App.jsx` — корневой компонент. Его мы заменим на `CafeApp`.
- `package.json` — скрипты и зависимости `react`, `react-dom`, `vite`.
- `vite.config.js` — плагин React: JSX и Fast Refresh.

Скрипты, которые стоит знать сразу:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

- `dev` — локальный сервер, обычно `http://localhost:5173`.
- `build` — папка `dist/` для хостинга.
- `preview` — локально посмотреть **собранный** билд, не режим разработки.

`node_modules` — скачанные пакеты. В git её не кладут: достаточно `package.json` и lock-файла (`package-lock.json` у npm).

## npm, pnpm, yarn

Все три ставят пакеты. Разница — в lock-файле и скорости. На Front Enjoy мы сами используем **pnpm**; в уроках пишем `npm`, потому что он приходит вместе с Node.

Не смешивайте менеджеры в одном проекте: появилось два lock-файла — удалите лишний и оставьте один способ установки.

## createRoot, а не ReactDOM.render

В React 18+ точка входа такая:

```jsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

const el = document.getElementById("root");
createRoot(el).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

Старые статьи показывают `ReactDOM.render`. Это API React 17 и ниже. В 19-й версии его нет смысла копировать: другое дерево корня, другие предупреждения, другой Strict Mode.

`document.getElementById("root")` может вернуть `null`, если в HTML нет такого id. В учебном шаблоне id есть. В реальном коде junior+ обычно проверяет элемент или ставит ненулевое утверждение, если HTML под вашим контролем.

## Что делает StrictMode

В разработке React **намеренно** дважды вызывает рендер и эффекты, чтобы поймать нечистые компоненты: «положил данные в массив во время отрисовки» всплывает быстрее.

На экране кафе это почти незаметно. В консоли могут удвоиться логи `console.log` из тела компонента. Это не баг Vite. На продакшен-сборке двойного вызова нет.

Строгий режим лучше не выключать «чтобы логи не двоились». Он как раз часть обучения.

## Vite или фреймворк

Официальный React предлагает два слоя:

1. **SPA на Vite** — то, что мы делаем с «Зёрнышком». Клиент рисует всё в браузере. Просто запустить, просто деплоить `dist` на любой статике.
2. **Метафреймворк** (Next.js, React Router в framework-режиме и т. п.) — когда нужны серверный рендер, файловый роутинг, серверные компоненты, SEO из коробки.

Для изучения библиотеки Vite честнее: вы видите `createRoot` и сами решаете, что подключать. Next прячет вход за своими файлами `app/` или `pages/`. К нему имеет смысл переходить, когда уже понятны компоненты, пропсы и состояние — иначе непонятно, где заканчивается React и начинается фреймворк.

Подключить React скриптом с CDN в готовый HTML тоже можно. Для приложения с JSX, импортами и HMR это хуже шаблона Vite: другой toolchain, другие грабли с версиями.

## Сборка в продакшен

```bash
npm run build
npm run preview
```

`preview` слушает другой порт и отдаёт уже минифицированный код. Если «на моей машине в `dev` работает, а на Netlify нет» — первым делом смотрите, что деплоите именно `dist`, а не запускаете Vite как прод-сервер.

Переменные окружения Vite читает из `.env` с префиксом `VITE_`. Секреты (токены, пароли) в клиентский бандл не кладут: всё с префиксом `VITE_` попадёт в браузер.

## Что запомнить

- Сборщик нужен, потому что браузеру нужны модули и JSX в понятном виде.
- Вход React 19: `createRoot` из `react-dom/client`, не `ReactDOM.render`.
- `dev` ≠ продакшен. На хостинг отправляют `npm run build`.
- Vite — чтобы учить библиотеку. Фреймворк — когда нужен сервер вокруг React.
