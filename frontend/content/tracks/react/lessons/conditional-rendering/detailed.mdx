Основное уже умеет `if`, тернарный оператор и `&&`. Здесь — когда какой приём не врёт, что React считает «пустым» и как не превратить карточку в ёлку из вложенных `? :`.

## Что React не рисует

В фигурных скобках можно получить значение, которое **не должно стать текстом на экране**. React специально ничего не показывает для `null`, `undefined`, `false` и `true`:

```jsx
{false && <span className="badge">Хит</span>}
{null}
{undefined}
{true}
```

На экране пусто. Поэтому `{isHit && <span>Хит</span>}` при `isHit === false` бейдж не рисует — это ожидаемо.

Другие значения React **выводит как текст**:

```jsx
{0}     {/* на экране появится 0 */}
{NaN}   {/* на экране появится NaN */}
{"0"}   {/* на экране появится символ «0» */}
```

Пустая строка `""` — исключение среди «почти пустых»: она тоже ничего не рисует. Число `0` так не умеет.

Отсюда ловушка со счётчиком. Левый операнд `&&` — ноль, React показывает ноль, абзац не прячется:

```jsx
{orderCount && <p>В заказе: {orderCount}</p>}
```

Для чисел пишите сравнение явно:

```jsx
{orderCount > 0 ? <p>В заказе: {orderCount}</p> : null}
```

Для булева флага `isHit && …` безопасно: слева не число.

Пустое описание можно проверить так — `""` ничего не даст, это удобно:

```jsx
{description && <p>{description}</p>}
```

С нулём тот же приём не сработает.

## Ранний выход из компонента

Иногда прятать нужно не бейдж, а всю карточку. Тогда условие — до разметки:

```jsx
function DrinkCard({ drink }) {
  if (!drink) {
    return null;
  }

  return (
    <article className="card">
      <h3>{drink.name}</h3>
    </article>
  );
}
```

`return null` — валидный рендер: «этого узла нет». Так же прячут гостевой блок, если пользователь уже вошёл. Не путайте с CSS `display: none`: элемент в DOM есть, скринридер и форма его ещё могут найти. Если какао нет в меню как позиции — `null` или не включайте его в массив. Если позиция есть, но закончилась — рисуйте «Нет в наличии», не скрывайте карточку стилем.

## Не прячьте ветки в тернарниках

Два коротких варианта в JSX — нормально:

```jsx
{inStock ? <button type="button">В заказ</button> : <p>Нет в наличии</p>}
```

Три этажа — уже нет:

```jsx
{
  inStock
    ? isHit
      ? <HitOrderButton />
      : <OrderButton />
    : isHit
      ? <HitSoldOut />
      : <SoldOut />
}
```

Так не читают на ревью. Вынесите в `if` над `return` или в маленький компонент `DrinkAction({ inStock, isHit })`. Карточка снова станет про название и цену.

## Вынесите условие в компонент

Бейдж «Хит» имеет имя. Пусть у него будет функция:

```jsx
function HitBadge({ on }) {
  if (!on) {
    return null;
  }
  return <span className="badge">Хит</span>;
}

function DrinkCard({ name, isHit }) {
  return (
    <h3>
      {name}
      <HitBadge on={isHit} />
    </h3>
  );
}
```

Внутри `HitBadge` условие одно. В `DrinkCard` его больше не видно. Это тот же принцип, что с `Header` и `Menu`: кусок с именем уезжает в свой компонент.

## && или явный null

Команда часто договаривается так:

- флаг да/нет → `{isHit && <HitBadge />}` или `<HitBadge on={isHit} />`;
- число, длина массива → сравнение, не `&&`;
- две разные разметки → тернарный оператор или `if`.

Не пишите `{isHit && <Badge /> || <Something />}`: приоритет `&&` и `||` легко перепутать. Лучше тернарник.

## Что запомнить

- `false` и `null` на экран не попадают, `0` — попадает. Для чисел сравнивайте явно.
- Целую карточку прячут через `return null`, не через CSS, если её не должно быть.
- Вложенные тернарники заменяют на `if` или на компонент ветки.
- `&&` — для булева «есть / нет», не для счётчиков.
