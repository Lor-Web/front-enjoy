Компонент — не «кусок HTML» и не класс в CSS. В рантайме это **функция, которую вызывает React**, когда нужно получить описание интерфейса. Вы сами её почти никогда не вызываете: пишете `<Welcome name="Аня" />`, а дальше работает reconciler.

На этой платформе шапка, дерево уроков и статья — отдельные функции. Квиз не знает, как устроена навигация, потому что React передаёт данные вниз по дереву, а не через общие глобальные переменные.

## Что происходит при `<Welcome />`

JSX не остаётся в бандле. Сборщик превращает тег в вызов. В современном React это не `React.createElement`, а функции из `react/jsx-runtime`:

```jsx
function Welcome({ name }) {
  return <h1>Привет, {name}</h1>;
}

// примерно то, что получит браузер:
jsx(Welcome, { name: "Аня" });
```

`jsx` (или старый `createElement`) **не рисует DOM**. Он возвращает обычный объект — *элемент*. Примерно такой формы:

```js
{
  $$typeof: Symbol.for("react.element"),
  type: Welcome, // сама функция, не строка
  key: null,
  ref: null,
  props: { name: "Аня" },
}
```

`$$typeof` нужен, чтобы случайный JSON из сети нельзя было выдать за элемент. `type` — либо строка (`"div"`), либо ваша функция (`Welcome`). Именно по `type` React решает: создать DOM-узел или вызвать компонент.

### Почему PascalCase обязателен

В JSX имя с маленькой буквы компилируется в **строку**: `<div>` → `type: "div"`. Имя с большой — в **идентификатор**: `<Welcome />` → `type: Welcome`.

Если написать `<welcome />`, React будет искать HTML-тег `welcome`, не найдёт вашу функцию и ничего полезного не нарисует. Имя файла ни на что не влияет: важна переменная, которая попала в `type`.

### Почему нельзя `Welcome()`

Вызов `Welcome({ name: "Аня" })` вернёт тот же элемент, но **обойдёт React**:

- хуки внутри `Welcome` привязаны к *файберу* — узлу в внутреннем дереве, который создаётся, только когда React сам вызывает функцию;
- родитель «не владеет» этим вызовом: при следующем рендере React не узнает, тот же это экземпляр или новый;
- `key`, `ref` и контекст до такой функции не доедут.

Пишите `<Welcome name="Аня" />`. React вызовет функцию сам, в правильный момент фазы render.

## Файбер: экземпляр компонента под капотом

На экране вы видите DOM. У React внутри — второе дерево: **Fiber**. Каждый файбер хранит:

- `type` и `key`;
- указатели на родителя, сиблинга, первого ребёнка (связный список, не массив — так дешевле обходить в цикле);
- пропсы и указатель на хуки (`memoizedState`);
- флаги обновления: этот узел нужно вставить, обновить, удалить, сдвинуть.

Один и тот же `Welcome` в разметке дважды — это **два файбера**. Поэтому у двух `<Welcome name="Аня" />` и `<Welcome name="Илья" />` разное состояние, если позже появится `useState`: это разные экземпляры, а не «одна функция на всех».

Функция компонента — рецепт. Файбер — конкретная порция этого рецепта на дереве.

### Render и commit

Обновление идёт в две фазы.

1. **Render.** React вызывает ваши функции, строит новое дерево элементов, сравнивает его с предыдущим файбером. DOM ещё не трогает. Эту фазу в будущем могут прерывать (Concurrent): поэтому рендер должен быть чистым — без записи в DOM, без сетевых запросов, без подписки на события.
2. **Commit.** Когда дерево готово, React применяет мутации: `appendChild`, смена текстового узла, вызов `useLayoutEffect` / `useEffect`.

Если в теле компонента сделать `document.querySelector` и поменять стиль, вы работаете вслепую: DOM может быть от прошлого коммита, а Strict Mode в разработке вызовет функцию дважды и эффект проявится два раза.

## Согласование: что React переиспользует

Когда родитель рендерится снова, React не уничтожает всё дерево. Он идёт сверху вниз и сравнивает `type` и `key`.

- Тот же `type` на том же месте — файбер **обновляется**: новые пропсы, функция вызывается снова, DOM-узел остаётся.
- Другой `type` (`Welcome` заменили на `p`, или на `Profile`) — старое поддерево **размонтируется**, новое создаётся с нуля. Состояние хуков пропадает.
- Список детей с `key` — React сопоставляет по ключу, а не по индексу. Без ключа сдвиг в массиве выглядит как «первый ребёнок получил чужие пропсы».

Отсюда практический вывод: не меняйте тип компонента в одном месте дерева «ради условия», если хотите сохранить состояние. Лучше один тип и разные пропсы, либо явное `key`, когда сброс состояния — это цель.

```jsx
function Welcome({ name }) {
  return <h1>Привет, {name}</h1>;
}

export function Home() {
  return (
    <main>
      <Welcome name="Аня" />
      <Welcome name="Илья" />
    </main>
  );
}
```

Два вызова — два файбера с одним `type`. React не клонирует разметку: он дважды выполняет функцию и дважды пишет текст в DOM, если текст изменился.

## Пропсы — это один объект

`<Welcome name="Аня" />` после компиляции даёт `props: { name: "Аня" }`. Деструктуризация `function Welcome({ name })` — сахар. Дети попадают туда же:

```jsx
<Card>
  <p>Текст</p>
</Card>
// props.children === элемент <p>
```

Родитель не «вшивает» разметку в ребёнка. Он передаёт значение. Ребёнок решает, куда поставить `children`. Соседние компоненты друг друга не видят: нет общего объекта «экрана», есть только дерево вызовов.

### Когда выделять новый компонент

Выносите кусок, если он:

- повторяется (карточка, пункт меню);
- имеет имя в голове («оглавление», «статус квиза»);
- разросся так, что родитель смешивает несколько задач.

Не дробите каждую строку. Каждый новый компонент — новый файбер, новый вызов функции, новая граница для хуков. Три строки без логики дешевле оставить на месте: читаемость важнее «идеальной гранулярности».

Глубокая вложенность `<div><div><div>` тоже стоит денег: это лишние DOM-узлы и лишние файберы. Оболочка нужна, когда у неё есть смысл — `AppShell`, `LessonArticle`, а не «обёртка чтобы сдвинуть на 8 пикселей».

## Что запомнить

- Компонент — функция `PascalCase`. React кладёт её в `element.type` и вызывает сам.
- Элемент — объект-описание. Файбер — экземпляр этого описания в памяти React. DOM — уже следствие фазы commit.
- Рендер чистый: никаких побочных эффектов в теле функции. Эффекты — после того, как дерево согласовано.
- Один и тот же компонент в двух местах дерева — два независимых экземпляра.
- Меняете `type` на месте — теряете состояние. Меняете только пропсы — состояние живёт дальше.
