Практики ниже — про форму компонентов, а не про стили. Их легко нарушить в небольшом файле, и цена растёт вместе с проектом.

## Имена и границы

- Имя компонента — **что это**, не **как сделано**: `LessonSidebar`, не `LeftDiv`.
- Один компонент — одна причина меняться. Квиз не должен уметь ходить в `localStorage` «заодно».
- Файл совпадает с именем: `lesson-sidebar.tsx` экспортирует `LessonSidebar`.

## Состав вместо копипасты

Если две карточки отличаются подписью и ссылкой — это один компонент с пропсами, не два файла. Копия разметки расходится после первой правки.

```jsx
// Плохо: почти одинаковые HeaderGuest и HeaderUser
// Лучше: Header с пропсом user
function Header({ user }) {
  return <header>{user ? <AccountMenu user={user} /> : <LoginLink />}</header>;
}
```

## Не прячьте дерево

Глубокая вложенность «обёрток ради обёрток» (`<Box><Box><Box>`) мешает читать структуру. Оболочка нужна, когда у неё есть смысл: `AppShell`, `Panel`, `LessonArticle`.

## Совместимость с остальным кодом

Компонент не импортирует соседний слайс того же слоя «потому что удобно». Общее выносят ниже. Так устроена FSD в этом репозитории: страница собирает виджеты, виджеты не знают друг о друге.
