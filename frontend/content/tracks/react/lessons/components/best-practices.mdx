Компоненты «Зёрнышка» должны читаться как карта экрана: шапка, меню, карточка, заказ. Ниже — правила, которые держат эту карту целой, когда файл вырастет.

## Одна задача на функцию

`Header` не считает заказ. `DrinkCard` не ходит за курсом валют. `CafeApp` не рисует внутренности карточки — он складывает части.

Если в функции появились «и шапка, и список, и модалка оплаты», выносите. Имя после выноса должно объяснять кусок без комментария.

## Не объявляйте компоненты во время рендера

Так делать нельзя: `DrinkCard` объявлен **внутри** `Menu`.

```jsx
function Menu() {
  function DrinkCard() {
    return <article>Латте</article>;
  }

  return (
    <section>
      <h2>Меню</h2>
      <DrinkCard />
    </section>
  );
}
```

На каждый рендер `Menu` создаётся новая функция `DrinkCard`. Для React это уже другой компонент: карточка сбрасывается. Когда внутри появится кнопка «В заказ» и своё состояние, счётчик будет обнуляться без видимой причины.

Так правильно — оба на одном уровне файла, рядом, не друг в друге:

```jsx
function DrinkCard() {
  return <article>Латте</article>;
}

function Menu() {
  return (
    <section>
      <h2>Меню</h2>
      <DrinkCard />
    </section>
  );
}
```

Внутри компонента можно держать обычные функции-хелперы, которые **не** рисуют как тег:

```jsx
function formatPrice(value) {
  return `${value} ₽`;
}

function DrinkCard() {
  return <p>{formatPrice(280)}</p>;
}
```

`formatPrice` пишут вызовом, не `<FormatPrice />`. Компонент — только то, что идёт в JSX с заглавной буквы.

## Имена как в UI

`Box`, `Wrapper`, `Item1` ничего не говорят. `OrderBar`, `DrinkCard`, `SoldOutBadge` — говорят.

PascalCase обязателен. `drinkCard` как тег React не отличит от HTML так, как вы думаете, и линтеры будут правы, когда закричат.

## Сначала композиция, потом абстракция

Не рисуйте `withCafeLayout(withTheme(Menu))` на третьем уроке. Два-три уровня вложенности JSX в `CafeApp` — нормально.

Общее выносят, когда **второй раз** понадобилось то же самое, а не когда «вдруг пригодится». Лишняя абстракция дороже копипасты из трёх строк.

## Именованные экспорты

```jsx
export function Menu() {
  /* … */
}
```

Так проще grep, автоимпорт и рефакторинг. Default уместен, если файл заведомо про один компонент и команда так договорилась. В одном PR не смешивайте стили без причины.

## Не наследуйте компоненты

`extends` для UI в React почти всегда означает, что проще передать данные или `children`. Иерархия классов плохо ложится на дерево «шапка над меню». Если хочется «почти как DrinkCard, только с бейджем» — это пропсы или обёртка, не subclass.

## Держите корень тонким

`CafeApp` — оглавление:

```jsx
function CafeApp() {
  return (
    <div>
      <Header />
      <Menu />
    </div>
  );
}
```

Когда сюда переедут заказ и фильтры, корень всё ещё должен читаться за пять секунд. Логику карточки оставьте карточке.

## Что запомнить

- Компонент = одна роль и имя с экрана.
- Объявление на уровне модуля, не внутри рендера.
- Композиция и пропсы вместо наследования и преждевременных HOC.
- Корень приложения — схема, не свалка разметки.
