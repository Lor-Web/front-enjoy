JSX выглядит как HTML, но это **синтаксис JavaScript**. Браузер его не понимает. Vite (через компилятор, совместимый с Babel) вырезает теги ещё на сборке и подставляет вызовы. В бандле нет строк разметки — есть объекты элементов и функции `jsx` / `jsxs`.

Пока вы думаете «я пишу HTML внутри JS», легко сделать ошибку: поставить `class`, вызвать обработчик сразу, вернуть два корня. Под капотом действуют правила JavaScript и объектная модель React, не парсер HTML.

## Во что компилируется тег

До React 17 почти везде вызывали `React.createElement`. С «automatic runtime» импортировать React из-за JSX не нужно: компилятор сам подставляет `jsx` из `react/jsx-runtime`.

```jsx
function TrackProgress({ read, total }) {
  const percent = Math.round((read / total) * 100);
  return (
    <p className="status">
      Прогресс: <strong>{percent}%</strong>
    </p>
  );
}
```

После компиляции это близко к:

```js
import { jsx, jsxs } from "react/jsx-runtime";

function TrackProgress({ read, total }) {
  const percent = Math.round((read / total) * 100);
  return jsxs("p", {
    className: "status",
    children: ["Прогресс: ", jsx("strong", { children: percent + "%" })],
  });
}
```

`jsx` — один ребёнок (или без детей). `jsxs` — несколько детей: так React сразу знает, что `children` будет массивом, и не тратит кадр на упаковку. В development вместо них `jsxDEV`: туда же попадают имя файла и номер строки для стека ошибок.

`createElement` никуда не делся. Его можно вызвать вручную. JSX — сахар над той же структурой элемента: `type`, `props`, `key`.

### Элемент — не DOM-узел

Результат `jsx("p", …)` — объект в памяти JS. Настоящий `<p>` в документе появится только на фазе commit, когда reconciler решит, что этот файбер надо вставить.

Поэтому `const el = <p />` не даёт вам узел, на котором можно вызвать `el.focus()`. Нет и HTML-строки: React не делает `innerHTML` из JSX. Сравнение идёт по деревьям объектов, затем точечные мутации DOM.

Если вставить объект элемента в обычный DOM через `append`, ничего не заработает: это не Node. Его понимает только React.

## Фигурные скобки — это JS-выражение

Внутри тега `{percent}` компилятор вклеивает выражение в `props` или в `children`. Допустимо то, что допустимо справа от `=` в JavaScript: переменная, вызов, тернарный оператор, `&&`.

Нельзя поставить инструкцию: `{if (x) …}`, `{const y = 1}`, цикл `for`. Их выносят **над** `return` — в тело функции, которое выполняется при каждом рендере.

```jsx
// Сработает при рендере, а не по клику: save() вызвался, пока строился элемент
<button onClick={save()}>Сохранить</button>

// В props.onClick должна лежать функция
<button onClick={save}>Сохранить</button>
<button onClick={() => save(id)}>Сохранить</button>
```

`onClick={save}` кладёт ссылку. `onClick={save()}` кладёт **то, что вернул** `save`. Если `save` ничего не возвращает, обработчик — `undefined`, а побочный эффект уже случился во время render.

### Что рисуется, а что нет

React не показывает `false`, `null`, `undefined` и `true`. Поэтому `{isDone && <Badge />}` работает: когда `isDone` ложно, ребёнок — `false`, узел не создаётся.

Ловушка: `{count && <p>Есть</p>}`. Если `count === 0`, React **нарисует ноль** — ноль честный ребёнок, не «пустой». Для числа безопаснее тернарный оператор: `{count > 0 ? <p>Есть</p> : null}`.

Объект (кроме элемента React) в children — ошибка. Массив — нормально: так `map` возвращает список элементов. Строка и число становятся текстовыми узлами.

## Почему атрибуты не как в HTML

JSX — выражения в JS-файле. `class` и `for` — зарезервированные слова языка, поэтому в пропсах `className` и `htmlFor`. События — `onClick`, `onChange`: это ключи объекта, camelCase принят в DOM Level 2 (`element.onclick`), не в HTML-атрибуте `onclick`.

Булево: `<input disabled />` компилируется в `disabled: true`. `disabled={false}` или отсутствие пропа — поле неактивно не будет. Для нативных тегов React в основном ставит **свойства DOM** (`node.className = …`), а не `setAttribute`, поэтому `className` совпадает с тем, как устроен узел в браузере.

`style` — объект, не строка. Ключи в camelCase: `marginInline`, не `margin-inline` в виде CSS-текста. Каждый рендер с новым литералом `{ color: "red" }` — новый объект; для статики это дёшево, для анимации на каждый кадр лучше CSS-класс.

```jsx
<p style={{ maxWidth: 672, marginInline: "auto" }}>Статья</p>
```

Классы в этом проекте собирают через `cn()`, а не конкатенацией строк в каждом файле: так проще не получить `"undefined"` в className.

### Один корень и фрагмент

`return` функции может вернуть один элемент. Два соседних `<h2>` и `<p>` без обёртки — синтаксическая ошибка JS (запятая / два выражения подряд), не «ограничение React».

Фрагмент `<>…</>` компилируется в `type: Symbol.for("react.fragment")`. Файбер есть, DOM-узла нет: дети поднимаются к родителю. `<div>` создаёт и файбер, и узел — лишняя обёртка в инспекторе, иногда ломает CSS-сетку.

У фрагмента может быть `key` (тогда пишут `<Fragment key={id}>`, короткий синтаксис ключ не принимает). Это нужно, когда `map` возвращает пару узлов без общей обёртки.

Самозакрывание `<img />` и `<Welcome />` обязательно: JSX ближе к XML. `<img>` без `/` — ошибка разбора.

## Зачем держать разметку в JS

Компонент квиза считает ответ и сразу рисует пояснение — одно дерево вызовов, одно место правки. Шаблоны в отдельных HTML-файлах заставляют прыгать между файлами и заново склеивать данные.

Цена: файл раздувается. Когда в JSX появляется третья вложенная тернарная сетка, кусок выносят в новый компонент, а не в «шаблон на стороне». Под капотом это снова `jsx(NewComponent, props)` — граница файбера, а не другой язык.

## Что запомнить

- JSX исчезает на сборке. В рантайме — `jsx` / `jsxs` и объекты элементов, не HTML-строка.
- Элемент ≠ DOM-узел. Узел появится, только если reconciler закоммитит файбер.
- В фигурных скобках — выражение. Инструкции и вызовы «прямо сейчас» принадлежат телу функции, не атрибуту.
- `className`, `htmlFor`, `onClick` — имена свойств JavaScript и DOM, не HTML-атрибутов.
- `false`/`null` не рисуются, `0` рисуется. Фрагмент не создаёт DOM-узел, `div` создаёт.
