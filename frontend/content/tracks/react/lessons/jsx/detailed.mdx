JSX выглядит как HTML, но это синтаксис JavaScript. Сборщик превращает его в вызовы, React получает объекты-элементы. Ниже — то, о что бьются, когда «вроде HTML, а не работает».

## Во что компилируется

Примерно так (упрощённо):

```jsx
<article className="card">
  <h3>Латте</h3>
</article>
```

становится вызовом `jsx("article", { className: "card", children: jsx("h3", { children: "Латте" }) })`. Современный Vite берёт runtime из `react/jsx-runtime`, в файле это не пишут руками.

Следствия:

- Это не строка HTML. XSS из `{userName}` сам по себе не вставит теги: текст экранируется.
- Соседние элементы — соседние аргументы, поэтому **нужен один корень** у `return`.
- «Закрой тег» обязателен: `<img />`, `<DrinkCard />`. Парсер JSX не такой всеядный, как браузер.

## Выражения, не инструкции

В `{ }` можно то, что **возвращает значение**: переменная, вызов, тернарный оператор, `&&`.

Нельзя положить `if`, `for`, `let`:

```jsx
{/* так нельзя */}
{
  if (drink.hit) {
    return <span>Хит</span>;
  }
}
```

Так можно: вынести `if` **над** `return` или написать `{drink.hit ? <span>Хит</span> : null}`. Условия подробно будут в своём уроке; здесь важно правило языка.

## Что не рисуется

React ничего не показывает для `null`, `undefined`, `true`, `false`. Поэтому `{false && <Badge />}` безопасен: `false` не станет текстом.

**Ноль — исключение.** `{0}` нарисует `0`. Отсюда классика `{count && <p>Позиций: {count}</p>}`: когда `count === 0`, на экране внезапно ноль. Для кафе лучше явно проверять, когда дойдёте до условий, или всегда писать тернарник.

Строка `"0"` и пустая строка `""` тоже особые: пустая строка ничего не даёт, `"0"` — символ. Не путайте с числом.

## className, htmlFor, style

`class` и `for` — зарезервированные слова JS, поэтому в JSX:

- класс — `className`;
- подпись к полю — `htmlFor`.

Инлайн-стили — **объект**, не строка:

```jsx
<p style={{ color: "var(--price)", fontWeight: 600 }}>{drink.price} ₽</p>
```

Ключи — camelCase (`backgroundColor`, не `background-color`). Для темы кафе обычно хватает CSS-классов; объектный `style` удобен, когда значение считается в JS (ширина по данным), не когда вы раскрашиваете карточку.

## Фрагменты

Лишний `<div>` вокруг двух заголовков ломает CSS-сетку и семантику. Если обёртка не нужна в DOM:

```jsx
function DrinkTitles() {
  return (
    <>
      <h3>Латте</h3>
      <p>280 ₽</p>
    </>
  );
}
```

У короткого фрагмента `<>` нет атрибутов. Если на список понадобится `key`, пишут `<Fragment key={...}>` — это уже урок про списки.

## Комментарии и spread

Комментарий только такой: `{/* цена со скидкой */}`. Синтаксис HTML-комментариев внутри JSX не используют.

Spread копирует пропсы:

```jsx
<article {...cardProps} />
```

Удобно, легко протащить лишнее (`className` затрётся следующим, события уедут не туда). В «Зёрнышке» пока лучше перечислять поля явно. Spread оставляйте, когда прокидываете нативный атрибут на DOM-тег осознанно.

## События — превью

`onClick`, `onChange` — camelCase, значение — функция, не строка `"add()"`. Подробно — урок про события. Если скопируете HTML `onclick="..."`, JSX не примет.

## Что запомнить

- JSX → вызовы React, не HTML-файл и не шаблонная строка.
- В скобках — выражения; `null`/`false` молчат, `0` — нет.
- `className` и объект `style`, один корень или фрагмент.
- Текст из `{данных}` экранируется; `dangerouslySetInnerHTML` — отдельный разговор.
