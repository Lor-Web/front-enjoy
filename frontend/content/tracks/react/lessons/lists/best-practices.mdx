Список в кафе меняется: закончилось какао, добавили раф, бармен переставил хиты наверх. Ключи должны это переживать.

## Id из данных, не из позиции

```jsx
{drinks.map((drink, index) => (
  <DrinkCard key={index} name={drink.name} />
))}
```

Сработало в демо — сломается, как только массив переставят. Сразу `key={drink.id}`. Если бэкенд id не дал, задайте его сами в исходном массиве, не в `map`.

Два одинаковых `id` — баг данных. Не маскируйте индексом.

## Никаких случайных ключей

`key={Math.random()}`, `key={crypto.randomUUID()}` внутри `map`, `key={Date.now()}` — на каждый рендер новый список с точки зрения React. Анимации, фокус, будущий стейт кнопки «В заказ» не выживут.

UUID один раз при создании напитка в данных — да. UUID в рендере — нет.

## Не мутируйте массив, по которому идёте

`drinks.sort(...)`, `drinks.push(...)`, `drinks.splice(...)` в теле `Menu` портят общий массив. Для показа «сначала хиты» считайте новый массив:

```jsx
const ordered = [...drinks].sort((a, b) => Number(b.isHit) - Number(a.isHit));
```

Исходник не тронут. Когда появится состояние, обновлять его будут иммутабельно — та же привычка.

## Пустое меню — текст, не пустота

Ноль карточек без пояснения выглядит как сломанная вёрстка. Одна строка «Сегодня всё разобрали» или «Нет напитков в наличии» закрывает вопрос. Длину проверяйте через `=== 0` / `> 0`, не через `&&`.

## map читаемый

Колбэк на двадцать строк JSX в `return` никто не ревьюит. Вынесите в переменную, как в основном уроке (`const cards = drinks.map(...)`), или в `function renderDrink(drink)`.

Не кладите `map` внутрь `map` без нужды: модификаторы внутри карточки — это пропсы `DrinkCard`, не вложенный список ради бейджа.

## Ключ на том, что возвращает map

```jsx
{drinks.map((drink) => (
  <li key={drink.id}>
    <DrinkCard name={drink.name} price={drink.price} />
  </li>
))}
```

Ключ на `<li>`, если именно его создаёт `map`. Не на внутренней карточке «на всякий случай» и снаружи одновременно без причины. Один уровень списка — один набор ключей.

## Что запомнить

- Стабильный `id` важнее короткой записи с индексом.
- Рендер не сортирует и не пушит исходный массив.
- Пустой список объясняют текстом.
- Ключ вешают на элемент, который порождает `map`.
