Основное: меню — массив, `map` рисует карточки, у каждой есть `key`. Здесь — зачем ключ на самом деле и почему индекс «почти всегда работает», пока не ломает бейджи.

## Что делает key

После обновления массива React сравнивает **новое** описание списка со **старым**. `key` говорит: «это тот же напиток, он просто сдвинулся», а не «первая карточка теперь какао».

Без ключей React по умолчанию смотрит на позицию. Удалили эспрессо из середины — вторая карточка может оставить себе состояние первой: фокус, ввод, позже — счётчик «В заказ». Бейдж «Хит» прилипает не к латте.

Поэтому `id` берут из данных: `"latte"`, `"espresso"`, uuid с сервера. Не из позиции в массиве.

Ключ должен быть:

- уникальным среди **соседей** (не во всём приложении);
- стабильным, пока живёт эта сущность;
- строкой или числом, не объектом.

```jsx
{drinks.map((drink) => (
  <DrinkCard key={drink.id} name={drink.name} price={drink.price} />
))}
```

`key` не приходит внутрь `DrinkCard` как `props.key`. React снимает его раньше. Если карточке нужен идентификатор — передайте `id={drink.id}` отдельно.

## Когда индекс допустим

`key={index}` не всегда катастрофа. Он терпим, если список:

- никогда не вставляют в середину;
- не сортируют;
- не фильтруют;
- у элементов нет своего состояния.

Статический «часы работы» из трёх строк — можно. Меню, где какао заканчивается и строка пропадает — нельзя: индексы сдвинутся, React перепутает хвост.

Не используйте индекс «пока нет id». Лучше временный id в данных (`id: "latte"`), чем индекс, который прикидывается вечным.

## Не эти ключи

```jsx
key={Math.random()}
key={Date.now()}
```

На каждый рендер ключ новый. React думает, что все карточки другие, и монтирует список с нуля: мигание, потеря фокуса, лишняя работа.

`key={drink}` если `drink` — объект: сравнится ссылка, после каждого `map` с новым литералом всё снова «другое».

Одинаковые ключи у двух латте — предупреждение в консоли и те же баги, что без ключа.

## key на фрагменте

Иногда `map` возвращает два узла без обёртки. Тогда ключ ставят на `Fragment`, не на короткий `<>`:

```jsx
import { Fragment } from "react";

{drinks.map((drink) => (
  <Fragment key={drink.id}>
    <h3>{drink.name}</h3>
    <p>{drink.price} ₽</p>
  </Fragment>
))}
```

`<>` атрибутов не принимает. Для списка с фрагментом нужен именно `Fragment`.

В «Зёрнышке» проще вернуть один `DrinkCard` с ключом на нём.

## Списки из других списков

Фильтр — обычный JavaScript до разметки:

```jsx
const available = drinks.filter((drink) => drink.inStock);

{available.map((drink) => (
  <DrinkCard key={drink.id} name={drink.name} price={drink.price} />
))}
```

Или цепочкой: `drinks.filter(...).map(...)`. Ключ по-прежнему `drink.id`, не индекс отфильтрованного массива.

Пустой результат — отдельная ветка, не «молча ноль карточек», если гостю нужно понять, что меню закончилось:

```jsx
{available.length === 0 ? (
  <p>Сегодня всё разобрали</p>
) : (
  available.map((drink) => <DrinkCard key={drink.id} {...drinkProps(drink)} />)
)}
```

Длину сравнивайте явно: см. урок про условия и ловушку `0 &&`.

## Не мутируйте массив в рендере

```jsx
function Menu() {
  drinks.push({ id: "raf", name: "Раф", price: 320 });
  return drinks.map(/* … */);
}
```

Каждый рендер дописывает раф. Список растёт, ключи путаются. Добавление — в обработчике события или в данных модуля, не в теле компонента. События — следующий урок.

## Что запомнить

- `key` — личность элемента между рендерами, не проп карточки.
- Id из данных. Индекс — только у мёртвого статичного списка.
- `Math.random()` как ключ хуже, чем нет ключа.
- Фильтруют массив, затем `map`; пустой список показывают явно.
